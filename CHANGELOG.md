# Changelog

All notable changes to this project are documented in this file.

This changelog is initialized from git commit history after `v1.0.0` and can be refined before upcoming releases.

## [Unreleased]

### Changed
- **`faceid_db.py` flyttad in i `core/`-paketet som `core/db.py` (move-only).** Audit-steg 4: datalagret (pickle + jsonl) flyttades via `git mv` till `backend/core/db.py` utan logikändring. `backend/faceid_db.py` är nu ett bakåtkompatibilitetsskal som aliasar sig självt till `core.db` i `sys.modules` (`sys.modules[__name__] = core.db`), så `import faceid_db` och `import core.db` refererar till *samma* modulobjekt — attributåtkomst och testernas monkeypatchning (`test_faceid_db.py` patchar sökvägskonstanter) förblir koherenta över båda namnen medan de ~19 importörerna migrerar. `test_faceid_db.py` samt de core-interna importörerna (`core/config.py`, `core/naming.py`) pekar nu på `core.db`; övriga importörer fungerar oförändrat via aliaset. PyInstaller-specens `hiddenimports` utökad med `core.db`.
- **En enda fil-hash-implementation (avdupliceras).** De två egna SHA1-fil-hash-implementationerna i `api/services/detection_service.py` (`_get_file_hash`) och `api/services/preprocessing_cache.py` (`compute_file_hash`) ersätts av delegering till den kanoniska `core.db.get_file_hash`. De tre var verifierat algoritmiskt identiska (SHA1 över samma bytes; chunk-storleken 8192 vs 65536 påverkar inte digesten — bevisat mot en sampelfil). De tunna wrapper-metoderna behålls eftersom klass-API:t anropas externt (`routes/detection`, `routes/preprocessing`); anroparna kontrollerar filens existens innan, så den kanoniska implementationens `None`-vid-fel-väg nås aldrig i praktiken (beteendebevarande).
- **Kanonisk källa för RAW/JPG-filändelser (`backend/core/files.py`, avdupliceras).** De fyra kopiorna av RAW-ändelsemängden — `detection_service._load_image`, `routes/preprocessing._RAW_EXTS`, `file_resolver.EXTENSION_PRESETS["raw"]` och `rename_service.SUPPORTED_EXTENSIONS` (kommentarerna medgav "keep aligned with…") — ersätts av import från nya `core/files.py` (`RAW_EXTENSIONS`, `STANDARD_EXTENSIONS`, `JPEG_EXTENSIONS`, `SUPPORTED_EXTENSIONS`). Mängderna var identiska mellan sajterna (RAW=9, supported/all=14) och är oförändrade efter flytten (per-sajt diffade före/efter). De två site-specifika delmängderna i `rename_service._extract_datetime_original` (EXIF-hjälparens PIL-/rawpy-grenar) lämnades orörda för att inte tyst ändra någon sajts accepterade ändelser. Följdstädning: det redundanta `sys.path`-hacket i `culling_service.py` togs bort (backend-roten är redan på path för `cli_config` — verifierat med import utan hacket).
- **Statistik-/räknekärnan lyft ut ur `rakna_spelare.py` till `backend/core/playerstats.py` (move-only).** Audit-steg som flyttar den delade, rena logiken (statistik + exkluderings-config) ur CLI-skriptet så FastAPI-backenden och CLI:t har en enda sanningskälla. Flyttade oförändrat till `core/playerstats.py`: `parse_filename`, `build_entries`, `segment_matches`, `bucket_counter`, `classify_deviation`, `summarize_counter`, `compute_baseline`, `compute_player_stats`, `load_exclusion_config`, `save_exclusion_config`, `resolve_exclusion_sets`, `resolve_always_markers` samt konstanterna `ALWAYS_GRUPP`/`ALWAYS_PUBLIK`/`CONFIG_DIR`/`CONFIG_FILE`. Terminalrendering (`render_bar`/`render_spark`/`print_section`), `Colors` och argparse/`main` blir kvar i `rakna_spelare.py`, som nu importerar från `core.playerstats` och re-exporterar de flyttade namnen (via `__all__`) för bakåtkompatibilitet. De tre API-tjänsterna (`player_count_service`, `file_resolver`, `culling_service`) importerar nu direkt `from core.playerstats import …`; de `sys.path.insert`-hack som bara fanns för att nå `rakna_spelare` togs bort ur `player_count_service` och `file_resolver` (culling behåller sitt hack — det behövs fortfarande för backend-rotens `cli_config`-skal). Paketering: `core.playerstats` tillagt i PyInstaller-specens `hiddenimports`. Testernas monkeypatch-mål (`CONFIG_DIR`/`CONFIG_FILE`, `load_exclusion_config`) pekar nu på `core.playerstats` där funktionerna bor.
- **`log_attempt_stats` och namn-/filnamnshjälparna utlyfta ur `hitta_ansikten.py` till `core/` — API:t importerar inte längre CLI-monoliten (move-only).** Audit-steg 2: `log_attempt_stats` flyttades till nya `backend/core/attempts.py`, och den rena namnklustret (`extract_prefix_suffix`, `is_unrenamed`, `collect_persons_for_files`, `normalize_name`, `split_fornamn_efternamn`, `resolve_fornamn_dubletter`, `build_new_filename`) till nya `backend/core/naming.py`. Funktionskropparna är oförändrade; `hitta_ansikten.py` importerar tillbaka de namn den faktiskt använder. `api/services/detection_service.py` importerar nu `load_config` från `core.config` och `log_attempt_stats` från `core.attempts` i stället för från `hitta_ansikten` — efter detta finns inga imports av CLI-monoliten kvar under `backend/api/`. `api/services/rename_service.py` avdupliceras: dess byte-identiska `normalize_name` ersätts av `from core.naming import normalize_name` (åter-exporteras därifrån för `manual_suffix_service`). De övriga portade namn-hjälparna i `rename_service` har medvetet avvikit från monolitens (fotografsuffix i regex, config-parametrar) och lämnas orörda. PyInstaller-specens `hiddenimports` utökad med `core.attempts` och `core.naming`.
- **`core`-paket infört; `cli_config`/`cli_matching`/`cli_image` flyttade dit (move-only).** Audit-steg 1 av att lyfta ut delad logik ur CLI-modullagret: modulerna flyttades via `git mv` till ett nytt `backend/core/`-paket (`core/config.py`, `core/matching.py`, `core/image.py`) utan någon logik- eller funktionsnamnsändring. De gamla sökvägarna finns kvar som tunna bakåtkompatibilitetsskal (`backend/cli_config.py` m.fl. → `from core.<modul> import *`) så befintliga importörer (`hitta_ansikten.py`, `api/services/culling_service.py`, arkiverade skript) fortsätter fungera oförändrat. Paketering uppdaterad: `packages = ["core"]` i `backend/pyproject.toml` och `core.*` tillagt i PyInstaller-specens `hiddenimports`. Culling-retentiontestet pekar nu på `core.config` i stället för skalet (monkeypatch måste träffa den riktiga modulen där `load_config` läser `BASE_DIR`/`CONFIG_PATH`).
- **Orphan CLI-skript arkiverade till `backend/scripts/archive/`.** Åtta fristående legacy-/engångsverktyg utan runtime-importörer (verifierat via grep i audit 2026-07) flyttades ut ur `backend/`-roten: `analysera_ansikten.py`, `hantera_ansikten.py`, `forfina_ansikten.py`, `ratta_ansikten.py`, `rensa_dlib.py`, `migrera_processed.py`, `inspect_encodings.py` och `update_encodings_with_filehash.py`. Inget raderades — de förblir körbara. Varje flyttat skript som importerar backend-moduler (t.ex. `faceid_db`) fick en liten `sys.path`-bootstrap i toppen som lägger till `backend/` (tre nivåer upp), så de kan köras direkt: `python scripts/archive/<verktyg>.py` från `backend/`. En `backend/scripts/archive/README.md` beskriver vad de är, varför de arkiverades och hur de körs. Följdändring: dokumentationens sökvägar till `rensa_dlib.py` m.fl. pekar nu på `scripts/archive/…`. `filer2mappar.py`, `rakna_spelare.py`, `rename_nef.py` och `hitta_ansikten.py` är fortsatt aktiva och lämnades i `backend/`-roten.

### Removed
- **dlib startup dry-run scan borttagen.** Servern körde vid varje boot en full-DB-genomsökning (`_check_dlib_encodings`) som letade efter föråldrade dlib-encodings och, om några hittades, loggade en varning + skickade en persistent svensk frontend-notis om att köra `rensa_dlib.py`. Skanningen är nu borttagen: en hel-DB-scan per uppstart elimineras (snabbare boot), och den svenska notis-wiringen tas bort med den. Borttagningsverktygen finns kvar och körs på begäran — `rensa_dlib.py` och remove-dlib-endpointen i refinement.
- **`face_recognition`-beroendet borttaget ur `backend/pyproject.toml`.** InsightFace är enda aktiva backend; `face_recognition` (som bygger dlib från källkod) importeras numera bara lat inuti `DlibBackend.__init__`, så paketet är optionellt och behövs inte för normal drift. `DlibBackend` och `rensa_dlib.py` behålls som borttagningsverktyg. Följdändring: CI- (`ci.yml`) och release- (`release.yml`) workflows installerar inte längre systempaketen `cmake`/`libdlib-dev` — backend-jobbet slipper därmed dlib-bygget och blir snabbare.
- Removed the dead `backend/api/services/db_service.py` stub (a ~103-line all-TODO `DatabaseService` scaffold with a module-level singleton, added in the initial Phase 2 backend commit and never implemented — nothing imported it). Also dropped its `api.services.db_service` PyInstaller `hiddenimport` from `ansikten-backend.spec` and the stale `# TODO: Implement using db_service` reference in `routes/status.py`.
- **Dead pre-FlexLayout renderer files removed from `frontend/`.** The running app loads `src/renderer/workspace-flex.html` + `src/preload/preload.js` (wired in `src/main/index.js`), not the root-level renderer that predated the FlexLayout workspace. Deleted the now-unreferenced `frontend/index.html`, `frontend/renderer.js`, `frontend/preload.js`, `frontend/styles.css` and the orphaned `src/renderer/hooks/useCapabilities.js` hook (its `hooks/index.js` barrel export was removed too). Follow-ups: `package.json` `build.files` no longer lists the four dead root files (packaged builds relied on `src/**/*` + `main.js` anyway), and the ESLint renderer glob dropped its `renderer.js`/`preload.js` entries. `frontend/main.js` (the real Electron entry, `"main": "main.js"`) is kept.
- Removed root-level `RENAME_MANUAL_FACES_PLAN.md` (a completed bug post-mortem — its fixes are recorded in this changelog) and `.luarc.json` (added in 2b67010 to silence Lua LSP false positives from `.venv`/`dist`; deliberately dropped now as editor-specific config that belongs in a personal global ignore rather than the repo).

### Fixed
- **Committade versionsnummer synkade med utgivna 1.3.0.** `backend/pyproject.toml` (och `version=`-strängen i `backend/api/server.py`, som `/health` returnerar) låg kvar på `1.0.0` medan `frontend/package.json` och den senast utgivna releasen är `1.3.0` — så en fristående backend rapporterade fel version. Båda backend-förekomsterna är nu bumpade till `1.3.0`. Release-bygget skriver ändå över frontend-versionen från `v*`-taggen (`npm pkg set version`), vilket nu är dokumenterat i [release-guide.md](docs/dev/release-guide.md) och [building.md](docs/dev/building.md) tillsammans med regeln att bumpa alla committade versioner ihop. Den kvarvarande trippel-dubbleringen av versionssträngen är noterad i ROADMAP.
- **`init_logging` kraschade när datamappen saknades (fresh machine / CI).** `init_logging()` körs vid import av `hitta_ansikten` — före `load_config()` som skapar `BASE_DIR` (`~/.local/share/faceid/`) — och `logging.FileHandler` kastade `FileNotFoundError` när mappen inte fanns. Loggningen skapar nu logfilens föräldramapp (`mkdir(parents=True, exist_ok=True)`) innan filhandtaget öppnas.
- **`cli_config` kraschade vid import på icke-macOS (t.ex. Linux CI).** `TEMP_DIR` var hårdkodad till `/private/tmp/ansikten` och gjorde `mkdir(parents=True)` vid import — sökvägen finns inte och går inte att skapa på Linux, så varje modul som importerar `hitta_ansikten`/`detection_service` kraschade med `PermissionError: '/private'`. `TEMP_DIR` väljs nu efter plattform: `/private/tmp` på macOS (den paketerade appen tillåter `/tmp` och `/private/tmp`, men inte systemets temp `/var/folders/…`), annars `tempfile.gettempdir()`. macOS-beteendet är oförändrat.
- **JPEG-rotation: felplacerad ansiktsruta och roterad miniatyr.** Foton med EXIF-orientering (t.ex. mobil-JPEG tagna i porträtt, `Orientation = Rotate 90 CW`) fick ansikten detekterade i det oroterade pixelplanet medan frontend (Chromium `<img>`) visar bilden EXIF-roterad — så bounding box-rutan hamnade ~90° fel (bredvid ansiktet) och miniatyren i sidopanelen visades liggande. Backend `_load_image` applicerar nu `PIL.ImageOps.exif_transpose()` innan pixlarna läses, så detektion och miniatyrbeskärning sker i samma orienterade plan som visas. RAW/NEF påverkades inte (libraw orienterar redan). Not: ansiktsminiatyrer som redan cachats på disk från en tidigare preprocessing av roterade JPEG:ar kan behöva regenereras.
- **Kvarhängande engelska flik-namn ("Image Viewer", "File Queue").** Fliktitlarna hade svenska översättningar ("Bildvisare", "Filkö") men visades ändå på engelska för den som sparat en layout innan översättningarna landade: FlexLayout serialiserar varje fliks `name` i den sparade layouten, och `Model.fromJson` kör aldrig om `t()` vid återställning. Layouten som läses från `localStorage` går nu genom `retranslateTabNames`, som återapplicerar aktuell översättning på varje känd modulflik (nyckel: flikens `component`/`moduleId`). Okända/manuellt omdöpta flikar lämnas orörda.

### Added
- **Committed lint configs + CI enforcement (Ruff + ESLint):** the repo had no committed linters. Backend now ships a `[tool.ruff]` config in `backend/pyproject.toml` (target py3.11, line-length 100, default `E`/`F` rules + import sorting `I`; `E402` ignored in `api/server.py` where routers are imported after app construction). Frontend ships an ESLint 9 flat config (`frontend/eslint.config.mjs`: `@eslint/js` recommended + `eslint-plugin-react-hooks` `rules-of-hooks` as error, `exhaustive-deps` off, browser/node/vitest globals per area; build output and `node_modules` ignored) with a `npm run lint` script. The **CI** workflow now runs `ruff check .` before `pytest` in the backend job and `npm run lint` before Vitest in the frontend job. `ruff` was added to the backend `dev` extra; `eslint` + plugins to the frontend dev dependencies. Config-first and pragmatic — the rules pass the existing code after safe autofixes (import sorting, dead-import/variable removal) rather than a wholesale reformat.
- **Karaktäriseringstester för `faceid_db` (`backend/tests/test_faceid_db.py`):** 27 tests pinning the current behavior of the data layer (pickle + jsonl) as a safety net for upcoming refactors — save/load round-trip against a temp dir (all path constants monkeypatched away from `~/.local/share/faceid`), `normalize_encoding_entry` (legacy bare arrays, dicts missing `backend`, passthrough, invalid-type → `None`), `get_file_hash` (known SHA1 + chunked reads for files > 64 KB), `rotate_logs` (no-op path, processed trim, attempt archive, oversized-log rotation via small synthetic limits), atomic write failure leaving the original intact with no `.tmp` litter, shared/exclusive flock usage, and `RestrictedUnpickler` blocking non-whitelisted classes.
- **Karaktäriseringstester för de tre tjänsterna (`backend/tests/test_detection_service.py`, `test_management_service.py`, `test_statistics_service.py`):** 41 tests pinning the current behavior of `DetectionService`, `ManagementService` and `StatisticsService` ahead of a refactor that moves them onto a unified `FaceDBStore`. Focused on the seams that refactor will touch rather than exhaustive coverage: **detection** — match-status decision logic (`_determine_match_case`), single-nearest matching with backend filtering (`_match_encoding`), detection-cache keying (file hash + distinct-pairs registry version), what `reload_database` clears, the confirm-identity mutation path (`known_faces` + `hard_negatives`), and debounced-save coalescing; **management** — rename / merge / delete / move-to-ignore against a real temp DB (asserting the persisted on-disk state and distinct-pairs registry follow-through), plus the 2.0 s TTL reload behavior; **statistics** — the `get_summary()` output shape for a synthetic DB + attempt log, and that it loads via `load_database`/`load_attempt_log` once per uncached request (spied via counters; marked with a NOTE since the refactor changes this). The InsightFace model is never loaded (fake backend), and all data-layer paths are monkeypatched away from `~/.local/share/faceid`.
- **CI-arbetsflöde för push och pull request (`.github/workflows/ci.yml`):** the repo previously only had the tag-triggered release workflow, so nothing gated `dev`/`master`. A new **CI** workflow now runs on every pull request and on pushes to `dev`/`master`, with two parallel jobs — **backend** (Ubuntu, Python 3.11: `pip install -e ".[dev]"`, then `pytest`) and **frontend** (Ubuntu, Node 20: `npm ci`, `npm test`, `npm run build:workspace`). A concurrency group cancels superseded runs on the same ref, and pip/npm caches speed up installs.
- **Granska ansikten — döp bilder utan ansikten manuellt:** when detection finds no faces, the review panel now shows a **"Lägg till namn manuellt"** button (and keeps keyboard focus) instead of a dead-end "Inga ansikten identifierade" message. Clicking it adds a manual name field — so a photo of an object (or a face the detector missed) can still be named and drive the filename, without the previously hidden `m` shortcut. Works the same in fix mode, which re-detects a processed file into this state. Uses the existing `addManualFace` flow (manual names already carry through to the rename pipeline).
- **Fritt filnamnstillägg (`Alt+Enter`) i Granska ansikten:** you can now attach a free-text suffix to the file you're reviewing (e.g. "vinbär" → `260401_140101_Vinbar.jpg`). It is **not** a person name — it never touches the face DB (`encodings.pkl`), name autocomplete, or the person pipeline; it only affects the filename. `Alt+Enter` opens a small dialog (prefilled with any existing suffix) with a live, normalized preview; `Enter` saves, `Esc` cancels. Normalization mirrors the person-name rules: spaces → `_`, diacritics folded (å/ä→a, ö→o), path-unsafe chars sanitized, repeated `_` collapsed. When the image also has confirmed faces the suffix is appended **after** the names; a faceless photo with only a suffix still renames. The suffix is persisted per file in a dedicated store (`manual_suffixes.json` under the faceid data dir) keyed by content hash (SHA1, stable across rename), separate from `attempt_stats`/`encodings`. New endpoints `GET`/`POST /api/v1/files/manual-suffix`; the rename preview/execute path reads the store and threads the suffix into filename building. Client normalizer `shared/manualSuffix.js` (unit-tested) keeps the preview in sync with the backend.
- **Radera aktuell fil till papperskorgen (`Cmd+⌫`) från Granska ansikten:** you can now soft-delete the file you're reviewing without leaving the review flow. `Cmd+Backspace` (Finder-konvention; även Arkiv → "Flytta till papperskorgen") moves the reviewed file to the same app-managed, restore-backed trash that Gallra spelare uses (`/api/v1/culling/trash`), prunes it from the queue and auto-advances to the next eligible file. **`Cmd+Shift+⌫`** (Redigera → "Ångra radering") restores the most recent one to its place in the queue — a dedicated shortcut, not `Cmd+Z`, which stays Review's face-undo. The keys are handled by the review surface's own keydown (gated to when Granska ansikten is visible and not while typing in a name field) rather than a global menu accelerator, so they never shadow Gallra spelare's own `Cmd+⌫` or trash the wrong file. The trash request carries the exact reviewed path and is executed in one place (FileQueueModule), so it acts on the right file and fires once. Deleting discards any unsaved review of that file (it's being trashed).
- **Papperskorg som egen vy (nåbar från menyn):** the app trash (soft-deleted files with restore) was only reachable from inside Gallra spelare. It's now a standalone **Papperskorg** module openable from **Visa → Papperskorg** — list, filter by type (jpg/raw), restore individual files, or empty (all or the filtered subset). The trash view is extracted into one shared `TrashPanel` component used by both the new module and Gallra spelare (single source of truth; no duplicated logic), backed by the same `/api/v1/culling/trash|restore|empty` endpoints. Gallra spelare passes a callback so its cull-loop undo stack and file list stay in sync after a restore/empty. The `trashGroup` filetype classifier moved to its own module (`trashGroup.js`).

- **CLI import subcommand (`ansikten import [MÅL]`)**: completing the workflow-verb trio alongside `faces` and `culling`, the terminal launcher can now open the Import module directly. `ansikten import` opens/focuses Importera with the memory card autodetected as before; `ansikten import ~/foto/2026` additionally pre-fills that folder as the transfer destination (persisted like any manual edit). The destination is a *target* (not a source or file list) and need not exist yet — it's created on transfer — so `--clear`/`--recursive` are no-ops for import. When the app is already running the args route into the live window; a bare `ansikten import` still suppresses the startup landing (unlike a bare `culling`, since import always opens its module). Parsing stays in `cli-args.js` (unit-tested); the destination is handed over via a dedicated `open-import` IPC channel mirroring `open-culling`.
- **Gallra spelare — översiktsläge (rutnät, Lightroom-likt):** culling now has a thumbnail/contact-sheet overview mode alongside the single-image loupe. A **Rutnät** toggle button in the filter bar switches between them — highlighted while the overview is active (the choice persists across restarts). The grid runs over the same file list and selection as the loupe, so navigation, culling (`x`/Delete/`Cmd+⌫`), undo (`Cmd+Z`) and `L` (Lightroom) all work on the focused thumbnail. Movement is 2-D: `←`/`→` step one cell, `↑`/`↓` (`k`/`j`) move a row, `Alt`+arrow pages. **Double-click** or **Enter** on a thumbnail opens it in the loupe; **Esc** in the loupe (when nothing is being edited) returns to the grid. Clicking a player in the stats column is mode-aware: in the grid a **single click highlights** that player's thumbnails (the rest dim, no filtering) and a **double click filters** to them; in the loupe a single click filters as before. Per-player highlighting is derived client-side from filenames — no extra backend data. Thumbnails come from the `preview-thumb` endpoint below; the grid component is `CullingGrid.jsx`, the 2-D geometry is the unit-tested `culling-grid-nav.js`.
- **Overview-thumbnail endpoint (`GET /api/v1/preprocessing/preview-thumb`):** a whole-frame downscaled JPEG for a JPEG or RAW file (query `path`, `size`; default 256px, clamped 32–1024), returned as `image/jpeg` with `Cache-Control: public, max-age=604800` and `X-Cache: HIT|MISS`. RAW files use the embedded preview (`rawpy.extract_thumb`, milliseconds) with a full-decode fallback; EXIF orientation is honoured. Cached under a new `grid/` kind in `PreprocessingCache`, keyed on a cheap path+mtime+size fingerprint (no full-file hashing), so filling a grid of hundreds of files stays fast and an in-place re-export refreshes automatically. Frontend client `shared/grid-thumbnail-cache.js` (blob-URL LRU + `useGridThumbnail` hook) mirrors the existing face-thumbnail cache. Infrastructure for the upcoming Gallra spelare grid/overview view.
- **Räkna spelare — configurable "always excluded" markers:** the built-in always-excluded names (team/group photos `Laget`/`FBK`, crowd `Klacken`) are no longer hard-coded — they're config-driven (config keys `always_grupp`/`always_publik`, or env `RAKNA_ALWAYS_GRUPP`/`PUBLIK`), defaulting to the built-ins so existing setups are unchanged. In the **Uteslutna** editor these are now editable under an "Alltid uteslutna (sparas)" section (Gruppbilder + Publik (alltid)): add your own (e.g. a `Forward` group label) or drop a built-in, then **Spara som standard**. Configured group markers are shown (previously the group row was fixed/locked). When a `RAKNA_*` env var shadows the config, the editor warns that saving won't take effect. ### Added
- **Remove redundant encodings** in Database Management: scans each person for redundant encodings — exact byte-identical duplicates, plus near-identical ones above an adjustable threshold — and lists `name: total → kept (N redundant)`, so re-processing bloat can be cleaned per person or all at once. Manual faces are never removed; default threshold `0` removes only exact duplicates. New endpoints `GET /api/v1/management/redundant-encodings` and `POST /api/v1/management/dedup-people` (supports `dry_run`).
- **Find duplicates** in Database Management: scans for pairs of distinctly-named people whose faces look like the same person (centroid cosine distance ≤ an adjustable threshold) and lists them closest-first, so accidental name variants (e.g. "Elis" vs "Elis Niemi") can be reviewed and merged with one click — "Keep A" / "Keep B" merges the other into the kept name. - **Twin recognition disambiguation**: at detection time, when a face's top two candidates are a confirmed-distinct pair (e.g. identical twins) and nearly equidistant, the suggested name is re-decided by a k-NN vote over both people's confirmed photos — more robust than the single nearest crop, which can pick the wrong twin. - **Twin-aware duplicate detection**: each candidate pair now also reports a head-to-head *separability* — a 1-NN leave-one-out score over both people's confirmed photos. Pairs that are close on centroid but cleanly separable (different people who look alike, e.g. identical twins) are flagged "likely distinct" and sorted last, instead of topping the list. Plus a **"Not a duplicate"** action that records the pair to a persistent confirmed-distinct registry (`distinct_pairs.json`) so future scans skip it, with an "Excluded pairs" list to undo. New endpoints `GET/POST /api/v1/management/distinct-pair(s)` and `POST …/distinct-pair/remove`.
